# 高危表达与语境豁免

这是诊断词表，不是字符串删除表。命中后先判断指代和技术语义，再决定展开、保留或删除。原文有定义时，优先用已有含义写清动作与对象；不能仅凭“有技术定义”豁免。所有保护区仍逐字保留，包括其中命中的词。

## 保留前的判断

逐处检查是否能准确展开，能则优先展开。保留理由限定为：属于保护区、必须沿用的正式名称、展开会损失技术精度，或刚说明过同一具体对象且再次展开会造成明显重复。后两项需要说明具体损失或重复，不能用来保留整段的标签堆叠。含义缺失时保留原意并指出需要补什么，不能把猜测当成定义。

## 分类词表

| 类别 | 高危表达 | 处理方式与豁免条件 |
| --- | --- | --- |
| 管理黑话 | 质量门、门禁、卡点、准入、准出、台账、水位 | 优先展开为原文的检查、记录内容或指标公式。例如已定义“水位 = 当前 QPS / 压测上限”时，可直接写比值及原有阈值。CI/CD、发布流程、容量管理的场景本身不构成豁免。原文缺定义则指出缺失，不能自行编阈值。 |
| 泛化的检查与记录 | 审计、留痕、审计闭环、审计产物 | 安全审计、依赖审计、依法留存的审计日志等精确用法可保留。泛指 review、运行记录或交付检查时，写清原文中的检查对象与记录内容，不自行补谁签字、保留多久或是否合规。 |
| 被滥用的技术词 | 边界、契约、护栏 | 有现成的职责、接口行为、限流、熔断或超时说明时优先展开。边界检查、API 契约等用于精确指代时，仍按上面的保留条件逐处判断。无明确对象的“建立全局护栏”需指出缺失。 |
| 比较起点与参照 | 基线、对齐基线、基线缺失 | 查清该处是首次采集结果、比较起点的快照，还是固定版本的压测结果，使用相应具体称呼。不能全文替换成“首次快照”，也不能把对比起点缺测改成项目没有任何历史数据。机器标识、正式测试名称或会损失精度的用法保留。 |
| 简写的状态与操作 | 冻结、解冻、唤醒 | 按原文写清停止和保留的操作、恢复条件。暂停每日采集且保留低频复查，不能写成停止全部采集；冻结数据与冻结采集任务不能混为一谈。原文没定义行为时指出不明之处；代码、字段、状态枚举保持原样。 |
| 商业咨询腔 | 护城河、矩阵、赋能、抓手、闭环、生态位 | 优先写原文中的具体优势、动作和对象。“矩阵”指代数对象、测试维度或权限映射时保留；“闭环”指真实 feedback loop 时保留，需有输入、反馈和调整动作。不能把泛泛的“已闭环”改成编造的处理记录。 |
| 空洞包装 | 证据、全方位、一站式、端到端、深入、全面 | 删除无信息量的包装，保留实际主张。“证据”指具体日志、测试结果或可定位材料时保留；“端到端”在分布式链路、端到端加密、端到端测试等精确语义中保留，即使不是分布式系统。范围确实明确且完整时，“全面”也不靠机械替换处理。 |
| 程度修饰 | 显著、大幅、极大、良好、卓越、强大、极致 | 用原文数据表达，或只删程度修饰并保留效果方向。“统计显著”有精确含义，不能删掉；“未见显著差异”不能改成“没有差异”。 |
| 确定性包装 | 众所周知、毫无疑问、必然、总是、从根本上 | 无依据的引导语可删；原文本身的确定性断言不能擅自降级为“可能”。保留断言并指出缺少依据。若是协议保证、数学命题或有条件的确定行为，保留条件与确定性。 |
| 名词化空转 | 进行清洗处理、实现能力提升、完成体系构建、构建可观测性能力 | 提取实际动作。“进行清洗处理”→“清洗”；“实现能力提升”若没有对象与措施，指出缺少信息，不把抽象词换成另一组抽象词。 |

## 识别词表之外的同类表达

先找词后面的实质内容。能展开时，就用已有对象、动作和条件替代标签；有语境豁免也可以改得更直接。不要机械地把“契约”全部换成“约定”、“基线”全部换成“标准”，也不要把“门禁”默认解释为阻止发布——必须有原文支持。

检查三个问题：

1. 这个名词能对应代码、图、指标或有定义的文档对象吗？概念本身有用但定义缺失时，指出缺失；不要把所有抽象概念都判成套话。
2. 这句双字或四字管理话，换个行业是否仍成立？若是，找原文中的主体、动作与结果。
3. 是否只有“进行 / 实现 / 完成 / 构建 + XX 性 / XX 化 / XX 能力”，却没有说明谁做什么、为什么做？把已有动作写出来，没有则不要补造。

例如“构建智能化协同能力”需要说明组件及其交互；“构建 AST”有明确技术对象，应保留。“矩阵乘法”不因为包含“矩阵”而需要改写。

## 句式与结构

| 命中形式 | 改写方向 | 必须保留 |
| --- | --- | --- |
| 首先 / 其次 / 最后 | 操作流程用编号步骤，论证按实际关系组织 | 顺序、依赖、前置条件 |
| 不是 X 而是 Y | 写明对象的行为、定义或适用条件；必要时分成两句 | 对 X 的否定与对 Y 的肯定 |
| 值得注意的是 | 直接陈述约束或风险 | 警告内容与严重程度 |
| 综上所述 / 总的来说 | 去掉引导语和重复总结，保留新增结论 | 结论、未决问题、行动项 |
| 三连排比、等长等重句 | 按条件、因果或步骤重组；独立事实可继续用列表 | 每条事实，不强接因果 |
| 强大的性能 / 卓越的体验 | 标题改成原文支持的对象或结果 | 测量范围和适用条件 |
| 超过两层的 bullet | 拆节或改写为段落 | 层级关系、步骤顺序、例外 |

## 豁免怎么记录

内部记录“位置 → 词语 → 该处的对象或行为 → 展开后的候选表达 → 是否必须保留及理由”，不需要在正文旁反复插注。影响用户理解的豁免可以写入主要改动列表，仍不超过 5 条。

例如：“第 2 段的‘性能基线’展开为‘v2.1.0 在同一负载下的压测结果’”；“`frozen` 是接口返回的状态值，逐字保留，周围正文解释实际暂停的任务”；“表格里的‘全方位’属于保护区，未改”。首次出现需要解释的术语，只有输入已提供定义时才可整合定义；否则在改动列表指出需要作者补充。
