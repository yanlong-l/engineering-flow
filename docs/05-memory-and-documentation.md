# 项目记忆与文档管理

## 目标

让下一次工作获得足够且适用的信息，同时控制过期内容、上下文体积和维护成本。保存全部对话不是默认方案。

## 记录分类

| 类型 | 示例 | 默认处理 |
| --- | --- | --- |
| 任务进度 | 完成了接口，尚缺重复请求检查 | 自动保存，完成后归档 |
| 程序观察 | 某命令的实际运行结果、接口实现位置 | 自动保存来源和快照 |
| 解释性判断 | 该设计可能用于防止重复提交 | AI 提议，不能自动成为事实 |
| 设计决定 | 为什么选择请求标识，接受什么限制 | 草稿随代码 Review 确认 |
| 项目约定 | 允许的状态转换、检查方法 | 版本化维护，记录来源 |
| 个人偏好 | 中文说明、较简短页面 | 个人配置，不混入团队决定 |

## 记录的可信状态与适用状态

两个维度分别记录：

- 确认状态：`proposed`、`confirmed`、`rejected`。
- 适用状态：`current`、`needs_revalidation`、`superseded`、`archived`。

“已确认”不等于永远适用；“需要复核”也不等于原记录已被证明错误。替代旧记录时保留关联和原因，避免两个互相冲突的决定同时作为默认上下文。

记录至少包含内容、类型、模块或路径范围、来源引用、确认信息、最后核验时间及对应快照。来源可以是代码、实际执行结果、PR 或明确的人类决定。仅有模型置信度不构成来源。

## 自动保存与确认

程序自动保存任务进度、工具结果、代码引用和候选记忆。对具体设计理由的归纳先作为候选。

人工可以在现有 Review 流程中确认设计决定与文档修改，不需要每条记录弹出额外确认框。未经过该过程的候选保持待确认状态；模型不能通过自评提升为人工确认。

## 检索流程

1. 核对当前项目、worktree、任务和代码状态。
2. 根据需求、关联路径和模块筛选记录。
3. 优先选择适用的已确认决定和可追溯事实。
4. 对候选、冲突和过期记录附状态说明；必要时先读当前代码复核。
5. 按配置的输入预算返回简短内容、来源和可继续读取的引用。

不把全部历史合并成一个不断增长的 Markdown。被预算排除的相关项应可继续检索；不能声称已经考虑了未加载的全部信息。

## 过期、冲突与清理

相关代码或配置变化、引用删除、设计决定被替代时，标记需要核验。按时间清理适用于临时进度和缓存，不能仅凭时间自动宣布设计事实仍然有效或已经错误。

两条记录矛盾时列出来源与版本，优先核对当前实现和已确认决定。如果实现与决定不一致，指出差异，不擅自把其中一方改写为正确。

相似记录可以建议合并，但不能丢失适用条件、否定、时间范围和来源。归档记录不参与默认检索，仍可追溯。

## 存储与团队共享

建议区分以下位置，名称在实现时确定：

- 本地运行目录，例如 `.engineering-flow/`：任务进度、执行输出、页面和可重建缓存，默认不提交。
- 仓库中的工程文档，例如 `docs/engineering-flow/`：经过 Review 的设计决定和维护知识，随代码提交。
- 项目配置：共享命令及流程要求。
- 个人配置：用户偏好和本机路径，不写入团队记录。

安装目录只存产品代码，不保存项目状态。共享文档与本地索引通过稳定 ID 和来源关联；避免人为维护两份同义正文。

上面的存储位置是规划，当前仓库尚未生成这些运行目录或忽略规则。

## 文档更新策略

默认更新现有说明。下列变化通常需要检查文档：

| 变化 | 检查的文档 |
| --- | --- |
| API 行为、参数或错误处理 | 接口说明与调用示例 |
| 数据结构或迁移 | 数据说明、部署与兼容性说明 |
| 运行和检查方法 | 开发、部署、排查手册 |
| 重要设计取舍 | 对应设计决定 |
| 普通局部修复 | 必要的任务及 Review 记录 |

文档分为人工维护、完整生成和混合三类。人工维护部分提供可审阅修改；完整生成部分标记来源；混合文档只更新约定区域。生成页面读取同一份结构化材料，不再单独维护一份解释。

## engineer-voice 集成

项目来源：[yanlong-l/engineer-voice](https://github.com/yanlong-l/engineer-voice)。当前尚未随 Engineering Flow 复制、安装或调用。

推荐流程：完成技术草稿与来源核对 → 显式调用 engineer-voice 做表达改写 → 检查技术语义和保护内容 → 纳入 Review 材料。

适用内容包括 PR 描述、Review 说明、设计决定和维护文档。代码、命令、原始日志、结构化状态和实际检查结果保持原样。模块不替代代码检查和事实核验。

集成时选择固定提交或版本，保留适用的许可与来源。模块更新需要运行语义回归样例，特别检查“未确认”与“未发生”、“超过”与“达到”、部分暂停与全部停止等差异。版本升级不能默默重写已经确认的历史决定。

## 与 Copilot 原生记忆的关系

可以利用原生 Memory 作为辅助，但不把其可用性、写入和每次检索作为产品必须满足的条件。Engineering Flow 的重要项目记录应当可查看、可审阅，并能在显式续接时读取。

原生记忆的覆盖客户端、设置和管理方式需要按实际环境核验。[GitHub 官方说明](https://docs.github.com/en/copilot/concepts/prompting-and-context/copilot-memory)
