# 演示、效果测量与开发交接

## 技术分享的表达方向

前面的 AI 分享已经说明单项任务可以提效。Engineering Flow 展示怎样支持更多工程师重复使用，并覆盖理解、验证、维护和下一次开发。

演示围绕实际成果，避免以其他人的案例是否夸大作为主要论点。可邀请领域工程师共同定义验收场景，并将其已有助手作为后续接入对象。

## 首次演示脚本

贯穿功能：测试平台批量执行 Case，页面超时重试不重复创建同一批任务。以下是现场演示路线；已运行的自动构造流程与既有宿主证据分别见 [M5 验收](14-m5-acceptance.md)，不把脚本替换正确实现描述成 Copilot 自动发现或修复缺陷。

1. 展示简短需求和验收条件，开始任务；显示原工作区已有改动。
2. Copilot 阅读相关代码并实现，运行配置的检查。
3. 打开 Review 页面，沿一条行为找到入口、关键逻辑和实际检查输出。
4. 呈现一个仍需人工判断的场景，例如多实例并发重复请求。没有检查的场景如实标为未覆盖。
5. 修改相关代码，刷新页面，展示旧检查和旧确认已不适用于新快照。
6. 修订并重新验证，保存设计决定、必要文档和交接记录。
7. 关闭会话，在新会话继续一个小需求，展示加载了哪些有效背景。

如果要展示产品发现预置问题，明确标为构造案例；不要把安排好的缺陷称为产品在真实项目中自动发现。

## 效果指标

| 指标 | 建议口径 |
| --- | --- |
| 完整交付经过时间 | 从明确需求到满足同一验收要求；等待时间单列 |
| 人投入时间 | 准备、操作、理解、Review、修复分别记录 |
| 评审准备与定位成本 | 找到关键实现、检查输出和未验证事项所用时间 |
| 评审有效性 | 已知问题识别、遗漏、误报和后续返工 |
| 续接成本 | 新会话找到正确模块的时间、重复说明和纠正次数 |
| 文档质量 | 实际行为一致性、来源和过期内容处理 |
| 重复使用 | 不同用户、项目和任务的实际采用及完成情况 |
| 前期与维护投入 | 安装、配置、产品开发、升级和故障处理 |

人投入时间和经过时间分别记录，不能相加或互相替代。工具建设成本与单次任务成本分列。

先在少量任务上观察，报告样本数、中位表现或范围，并保留失败案例。尽量使用相近难度和一致验收要求；重复同一任务的熟悉效应、模型与环境变化应记录。未经控制的小样本不能作为普遍收益承诺。

不以生成代码量、文档数量、页面停留时间或模型自评作为产品成功标准。

## 交接给下一次开发

当前进度统一查看根目录 [STATUS.md](../STATUS.md)。本节定义跨会话交接方法，不重复维护另一份长期进度清单。

2026-11-08 已完成 M0–M4 当前本机支持范围的实现与验收，M5 也已建立可重复的构造流程与首版逐项范围。实际结果见 [M5 验收](14-m5-acceptance.md) 和 STATUS；自动经过时间不代表工程师投入，真人语义评审和真实团队收益未测量。

### 什么时候换会话

一个阶段可以包含多个会话。优先在以下条件满足后交接：

1. 本轮小目标有可复现结果，或明确记录了未完成的具体位置。
2. 相关检查的命令、结果、适用代码版本和未验证事项有记录。
3. 分支、提交及未提交改动可识别；已有和归属不明内容不自动归入本轮。
4. `STATUS.md` 已更新，重要技术决定及受影响的使用说明已同步。
5. 下一步是一个具体动作，不只写“继续开发”。

建议在完成本轮范围后形成清楚的本地 Git 检查点。尚未提交也可交接，但应保留改动并说明归属、位置和检查范围。切换会话不要求所有阶段已完成，也不要求把失败记录改成通过。

### M5 以后继续开发

先读 STATUS，核对累计未提交内容、实际分支和最后检查的源码指纹。M4 提供一个 Copilot Agent、两个内部 Skills、八组共用 Core 的 MCP 工具、只读 doctor/plugin inspect 与绑定安装。实际 Copilot 已使用干净 wheel 安装完成检查、分页读取规则、改写和交接；程序保护通过仍不是人工语义确认。

以 M5 报告的证据对应表和 `make pilot-check` 复现，优先补真实人工语义判断、工程师理解/续接观察或目标电脑的安装试用。已通过的程序结果按对应源码及环境复用；只对实际缺口和变化重新验证。个人展示仅有按调用 summary/full，持久设置/多预设延期，已在首版范围中记录。

产品 Hooks 保持关闭，事件探针不证明自动保存或失败/超时语义；无 Hooks 显式路径已验证，不要求为 M5 另建自动化系统。构造案例不能外推真实团队收益；M5 验收结果与公开发布分别决定。

### 后续会话通用提示

```text
继续 Engineering Flow。先读 AGENTS.md、README.md、STATUS.md 和当前单元相关设计。
先核对仓库、分支、worktree 和当前改动，再以 STATUS.md 的最新状态继续。
本轮完成其中列出的下一项交接单元；如果状态与代码不一致，先核对并修正记录。
保留已有改动，运行与本轮相关的检查；结束时更新状态、结果、未完成事项及下一步。
```

### 会话交接记录内容

`STATUS.md` 保留最新摘要，长期决定记录到决定文档，原始日志留在适当的本地目录。按需要记录以下内容，不复制全部对话：

```text
更新日期：
当前阶段 / 本轮小目标：
已完成的具体行为：
仓库 / worktree / 分支 / HEAD：
未提交改动及归属：
实际检查命令、结果、对应代码状态和输出引用：
失败、未运行或未验证事项：
重要决定及来源：
下一步第一项操作：
```

这些是本项目开发期间的文件交接约定。产品已有显式任务保存与交接材料生成，实际支持范围见 STATUS；生成材料本身不宣告验收完成。

项目目前不要求立即解决所有待定事项。普通实现选择可按现有信息推进；只有影响产品方向或无法验证的环境条件需要进一步澄清。
