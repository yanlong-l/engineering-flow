# 开发路线与验收

本路线按可交付成果排序，不预设日期或虚构工作量。阶段完成以实际运行结果为准。

## 阶段总览与当前起点

从准备到首版验收共 **6 个阶段：M0–M5**。阶段是成果边界，会话按可验收的小目标拆分，两者不必一一对应。

| 阶段 | 主要成果 | 结束时应能证明什么 |
| --- | --- | --- |
| M0 环境与选型 | 可用宿主组合、工程接入方式和初始技术选择 | 真实 Copilot 能加载入口并调用工具；已知限制有记录 |
| M1 任务与状态基础 | 任务存取、工作区身份、快照和恢复 | 进程重启能恢复，已有改动和不同 worktree 不混淆 |
| M2 检查与 Review | 真实检查、快照绑定、固定页面与评审记录 | 需求可定位到实现和证据，代码变更后旧结果不被沿用 |
| M3 记忆与文档 | 有来源的相关记录、受影响文档和交接 | 新会话能取得适用上下文，候选、冲突和过期内容可识别 |
| M4 产品集成与体验 | 正式插件、少量用户动作、配置、诊断与安装说明 | 在明确的支持环境按文档安装后，能完整跑通流程 |
| M5 试点与首版验收 | Python 示例上的完整任务、缺陷修复与范围说明 | 首版要求逐项有验收依据，形成可安装的首版候选 |

2026-11-08 更新：M0–M4 已完成当前本机支持范围的实现与验收。M5 新增可重复运行的 Python 构造试点，FR-01–FR-16 与 AT-01–AT-16 的证据及范围逐项记录在 [M5 验收](14-m5-acceptance.md)。安装与真实 Copilot 结果沿用并核对产品指纹，产品 Hooks 保持关闭。首版技术候选保留 dev8；本机实际检查以 STATUS 为准，真人语义评审和真实团队收益仍未验证。

最新进度和下一会话的目标统一维护在 [STATUS.md](../STATUS.md)。环境或版本未变时沿用已记录的验证结果；有相关变化才补充验证。

## M0：验证宿主能力并确定技术选型

记录 IDE、Copilot 版本、公司策略、运行环境和目标技术栈。用最小样例验证自定义 Agent、插件安装、一个本地工具调用以及候选 Hooks 的实际事件。

产出：兼容性记录、最小可安装包或明确的替代路径、技术选型决定。

验收：新会话中能选择入口并实际调用测试工具；支持与不支持的能力均有记录。Hooks 不可用时，显式操作仍可完成核心流程。

此阶段不要先建设完整页面或依赖未经验证的自动触发能力。

## M1：任务、快照与持久化

实现项目与 worktree 身份、任务创建与恢复、启动时已有改动、快照、版本化存储和显式 checkpoint。

验收：重启进程后可恢复；同仓库不同 worktree 不混淆；已有改动可识别；损坏记录和并发写入有明确处理。

## M2：检查执行与 Review 页面

实现配置检查执行器、真实输出采集、结果与快照绑定、适用性计算、结构化 Review 材料和固定模板 HTML。

AI 解释由 Agent 根据需求和代码形成，程序执行记录由执行器产生，页面分别展示。首版提供可靠文件与 diff 引用，不要求全系统调用图。

验收：至少覆盖通过、失败、执行错误、未运行、跳过、过期六种展示；修改代码后不继续沿用旧确认；脚本样式文本安全展示为内容。

## M3：相关记忆、文档与交接

实现候选记忆、来源引用、确认与适用状态、按任务检索、过期检查、文档修改建议和交接。

集成固定版本的 engineer-voice，并保留缺少该模块时的降级方式。用已有语义样例核对表达改写，不以模型自评代替。

验收：新会话可以基于正确背景继续；过期和矛盾记录有提示；候选不被当成人工确认；文档没有被静默改成与实现不一致的结论。

## M4：完成 Copilot 产品体验

将主 Agent、内部 Skills、MCP/CLI 接口和可用 Hooks 组织为插件。只暴露少量用户动作；提供安装、诊断、升级和最低支持说明。

插件的打包与工具调用从 M0 即开始验证，本阶段完成的是正式协作流程，不把插件集成拖到所有功能完成后才首次尝试。

验收：按照文档，在干净环境安装后跑通完整任务。无需手动拼装一组 Skills；核心状态逻辑在不同入口一致。

当前结果：按[安装说明](13-installation-and-upgrade.md)在无系统包的 venv 安装 wheel 与固定 MCP SDK，完成 dev7→dev8→dev7→dev8，保留 v6 历史；真实 Copilot 使用该安装完成续接、checkpoint、检查、Review、文档改写和交接。额外文件/Hooks、错误版本/环境、移动工作区和分支错配明确拒绝。默认展示可按调用选择 summary/full，不改变项目 required；暂不提供持久个人配置或快速/扩展预设。此范围内 M4 完成，跨电脑兼容性与 M5 首版验收另行进行。

## M5：试点与首版验收

在少量真实任务中评估理解、验证、返工和续接成本。根据真实问题决定是否增加 IDE Webview、专项模块、团队共享或外部连接。

首个试点没有现成业务仓库，先用自建 Python 示例完成可重复运行的任务与端到端验收。构造数据和预置问题明确标注，真实团队收益另行观察。扩展功能按后续优先级选择，不把全部 P1/P2 作为首版完成条件。

验收：报告样本、实际结果、失败情形和前期投入，不外推未经验证的全部门收益。

当前实现：`make pilot-check` 在独立构造 Git 仓库中运行预置缺陷失败→修复→检查/跳过→Review→文档应用后的失效→新进程续接；保留逐步原始输出。项目新增 required `pilot`，不削减原有检查。首版逐项范围、确认模拟与固定语义样例的边界见 M5 报告；自动脚本时间不作为人工成本或收益。

## 首个纵向场景

建议使用熟悉的测试平台后端：批量执行 Case，同一个页面操作因超时重试时不能重复创建任务。

需求、实现、检查、Review 和续接全部围绕这个功能。用户原有平台无需接入真实生产设备；可用构造或脱敏数据完成首轮验证。

## 关键验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AT-01 | 创建任务前工作区已有改动 | 记录为已有；不全部归于当前任务 |
| AT-02 | 两个 worktree 有相同分支名或相似路径 | 根据工作区身份隔离，不误恢复 |
| AT-03 | HEAD 不变但文件已修改 | 快照变化，相关结果重新判断 |
| AT-04 | 检查运行中代码改变 | 不标为当前代码已验证 |
| AT-05 | 命令失败、超时或不存在 | 分别记录失败或执行错误，不通过 |
| AT-06 | AI 说检查通过但没有执行记录 | 显示未运行或无可核验结果 |
| AT-07 | 已 Review 后继续修改代码 | 旧确认留在旧快照，新改动待核验 |
| AT-08 | 已确认记忆关联代码被删除 | 标记待核验，检索时不当现行规则 |
| AT-09 | 同一模块两条决定矛盾 | 保留来源与差异，不自动合成结论 |
| AT-10 | 工具中断、写入中断、重启 | 可恢复最后有效记录，不虚构完成 |
| AT-11 | 无 Hooks 环境 | 显式操作可跑通主流程 |
| AT-12 | 个人关闭必需检查 | 不把项目要求移除，不把跳过算通过 |
| AT-13 | 页面含 HTML/脚本样式日志 | 按文本展示，不执行 |
| AT-14 | 旧静态页面对应旧代码 | 明确快照，刷新后显示失效状态 |
| AT-15 | 工程表达改写改变条件或否定 | 验收失败，保留原文或撤回错误改写 |
| AT-16 | 模型请求直接写入人工确认 | 不接受为真实人工确认 |

## 测试投入

重点测试状态、来源和失效这些可能让工程师作出错误判断的行为。真实 Git 临时仓库用于验证快照、删除、未追踪文件和 worktree；构造进程用于检查超时、失败和中断；页面进行实际打开和引用核对。

宿主兼容性需要在目标 Copilot 中实际验证，不能只用单元测试模拟。模型输出用有来源的固定案例和人工判断评估；避免将第二个模型的认可作为唯一标准。

## 开发顺序建议

M5 构造试点与首版证据已建立。后续优先依据 STATUS 和 M5 报告选择真人语义评审、目标电脑试用或实际业务任务；不默认扩大为 IDE Webview、自动 Hooks、团队后台或 P1/P2 功能。

M2-1 已实现最小纵向切片：创建任务 → 保存快照 → 运行一次真实检查 → 生成最简 Review 材料 → 重启后继续。这是第一个可以展示整条产品主路径的里程碑，不等于首版全部完成。

在这个切片正确以后再扩大字段和界面。先保证旧结果不会误导，再丰富解释与专项能力。

## 会话交接边界

推荐在一个可复现的小目标完成、相关检查已经执行、工作区内容和下一步已记录后换会话。M2 可以分为检查执行与页面两个单元，M3 可以分为记录续接与文档集成，M4 可以分为插件集成与安装/体验验收。

需要中途停止时，也可以保存代码和状态后交接：标明失败、未完成及未运行内容，说明接下来首先要做什么。未完成的单元仍保持未完成，不为换会话修改验收结论。

## 首版完成的判定

M4 完成代表主要实现已集成；M5 验收结束才形成首版候选。首版完成需要：

- 首版需求表中的适用 P0 项有实际实现和验收依据；范围调整记明原因。
- Python 示例上的开发、真实检查、Review、修订、文档与新会话续接完整跑通。
- 关键可信度场景按要求验证，必需检查的失败、未运行和跳过不能算通过。
- 明确支持的客户端/版本、安装步骤、限制及已知问题，并完成干净环境安装验证。

公开发布、发布可见性和后续 P1/P2 扩展分别决定，不从“首版验收通过”自动推导为已经发布。
